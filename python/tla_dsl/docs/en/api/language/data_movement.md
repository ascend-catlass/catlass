# Data Movement

[Language Reference](index.md) | [API Quick Reference](../quick_reference.md)

Tensor copies between on-chip and global memory, and UB register load/store.

## `tla.copy`

**Source:** [`catlass.core_api.copy`](../../../../catlass/core_api.py)

Description:

Copy a tile from `src` to `dst`. Supported routes and dtypes are listed
after Constraints.

Prototype:

```python
tla.copy(dst: Tensor, src: Tensor, params: CopyParams | None = None, *, scale: Tensor | None = None, cache_policy: CachePolicy | None = None) -> None
```

Parameters:

- `dst` (`Tensor`): Destination tile. Required.
- `src` (`Tensor`): Source tile. Required.
- `params` (`CopyParams | None`): Path-specific params:
  `CopyL0C2DstParams`, `CopyUbToGmParams`, or `CopyPadParams`.
  Default `None` (exact-byte copy / no pad / default fixpipe).
  - `CopyL0C2DstParams`: L0C → GM/L1/UB fixpipe options
    (`unit_flag`, `relu_enable`, `quant_mode`, `quant_scale`,
    `quant_offset`, `quant_tensor`, `l0c2ub_mode`, `atomic_mode`).
    See the Cube fixpipe table for supported combinations.
  - `CopyUbToGmParams`: UB → GM writeback options. Field:
    `atomic_mode` (`AtomicMode`, default `NONE`).
  - `CopyPadParams`: enables DataCopyPad (`isPad=true`) on GM→UB or
    GM→L1 VectorLayout→VectorLayout (cube). Supported routes/dtypes
    are listed in the CopyPad table below. Optional fields
    (may be set together; each defaults to `0`):
    - `left_padding`: elements padded on the left of the innermost
      axis (compile-time int or runtime integer/index SSA). Must
      not be bool/tla.Bool/i1.
    - `right_padding`: elements padded on the right of the innermost
      axis (same type rules as `left_padding`).
    - `padding_value`: fill for padded elements. Default `0` means
      zero-fill. Must match the source element dtype (see
      Constraints); for `hif8`/`fp8`/`fp4x2`/`i4x2` use an 8-bit
      integer bit pattern (bare `int` or matching Numeric with int
      host), not a float.
- `scale` (`Tensor | None`): L1 OCP `e8m0` shared-exponent tile for
  L1→L0A/L0B MX load. Stored as `i8`/`u8`; destination tag is
  `tla.arch.zZMxScale` (L0A) or `tla.arch.nNMxScale` (L0B).
  Default `None`.
- `cache_policy` (`CachePolicy | None`): Optional L2 cache hint for the
  GM endpoint of this copy (`DISABLE` / `NORMAL`). On `GM→*` routes it
  tags the GM src; on `*→GM` routes it tags the GM dst. There is no
  GM→GM copy route. Default `None` (omit the hint; BC uses NORMAL).
  On non-GM routes any explicit value (including `NORMAL`) is rejected;
  omit the argument instead.

Constraints:

- Must be called inside a `@tla.kernel`-decorated kernel function.
- Must be called inside `tla.cube()` or `tla.vector()`.
- Copy size follows each tile's `origin_shape`.
- UB-to-GM and L0C-to-GM copies accept
  `params.atomic_mode`. Use `AtomicMode.ADD`, `MAX`, or `MIN` to combine
  this write with the old GM value. The default, `NONE`, overwrites it.
  The GM element type must be i8, i16, i32, f16, bf16, or f32 for atomic
  writes. For L0C, conversion, quantization, and ReLU take effect before
  the atomic operation.
  For UB-to-GM, supply `CopyUbToGmParams` or omit `params`. Within
  that parameter object, `atomic_mode` must be an `AtomicMode` member
  and defaults to `AtomicMode.NONE`.
- When `params` is `CopyPadParams`: see the CopyPad coverage table
  below. Side counts must not be bool/tla.Bool/i1; a static side
  count must satisfy pad bytes ≤ 32B; with static extents, dst
  innermost ≥ src + left + right. GM→UB opens hif8/fp8/fp4x2/i4x2
  (scalar `f4e2m1`/`f4e1m2` Pad stay closed); GM→L1 adds hif8 only
  (fp8/fp4 Pad stay closed on GM→L1).
- `CopyPadParams.padding_value` must match the source element dtype
  (i1: bool/tla.Bool; integer: bare int or same-dtype Numeric;
  float f16/bf16/f32/f64: bare float or matching float Numeric;
  hif8/fp8/fp4x2/i4x2: 8-bit integer bit pattern via bare int or
  matching Numeric with int host — no float encode; bare int 0 is
  the dataclass default zero-fill). Runtime non-i1 is an i64 bit
  pattern; runtime i1 SSA is unsupported. For 8B (`i64`/`u64`/
  `f64`), only a static zero fill is guaranteed; runtime is not
  value-checked and the BC always zero-fills.
- On Ascend 950, two logical rank-3 views `(B, M, N)` select batched
  GM-to-L1 layout conversion. FP8 supports RowMajor→zN and
  ColumnMajor→nZ; E8M0 supports the four GM MX-scale routes below.
  Batch count is `origin_shape[0]`; source and destination matrix
  strides are each layout's leading stride, in elements. Inner strides
  retain their 2-D meaning. Both logical extents must match, including
  runtime values. Zero batches or zero matrix extents perform no DMA.
  Other rank-3 layout/dtype combinations fail at compilation instead
  of falling back to a 2-D copy.
- Batched copies require `params=None` and `scale=None`, a batch count
  in 0..65535, and positive destination batch strides aligned to 32
  bytes and at most 65535 32-byte blocks. E8M0 source matrix strides
  must preserve exponent pairs. Runtime geometry must satisfy the same
  constraints. The caller supplies enough backing storage and disjoint
  destination matrices; interleaved NZ layouts are permitted.
- Packed fp4 is staged as bytes on the routes that convert the
  descriptor before copying -- GM->UB, UB->GM and UB->L1 -- so each
  tile's innermost `origin_shape`, its innermost origin coordinate and
  the stride the conversion halves must all be even: two fp4 elements
  share a byte, and an odd one of the three lands half a byte off. The
  halved stride is the row stride of a `RowMajor` tile and the pitch
  between C0 columns of a `zN` tile, so a `zN` destination on UB->L1
  carries the requirement as well. A value known only at run time
  cannot be shown to be even and is refused as well. The cube's GM->L1
  fp4 route keeps its own denomination and is unconstrained, and
  `tla.experimental.mx_to` still accepts an odd extent -- such a tile
  simply cannot be staged through a byte descriptor.
- `scale` is only valid on L1→L0A/L0B; the loaded tile must then be
  consumed by `tla.mmad_mx`.
- For MX scale destinations (`zZMxScale` / `nNMxScale`), the source
  tile must span full L1 rows; stack scale blocks along rows.
  Checked only when row pitch is statically known.
- UB→UB counts in whole 32-byte blocks; rows round up. Rejected if the
  origin is not 32B-aligned, or multi-row pitch cannot hold the rounded
  row. Destination tagged `ColumnMajor` is a transpose: tile shape must
  be whole 16×C0 blocks, or 32×32 for 1-byte types.
- `GM`→`L1` / `L1`→`biasbuf` contiguous runs use rank-1 `VectorLayout`;
  multi-row bias tiles are not representable — slice one row.
- PER_CHANNEL dequant parameters (`CopyL0C2DstParams.quant_tensor`)
  are a rank-1 `VectorLayout` tile in the `L1` address space, element
  type `u64`, unit stride. One element carries the dequant parameter
  shared by every element of one output channel, so the run must hold
  exactly one element per channel of the destination tile, ``originShape[1]``
  after `tile_view` cropping. When both lengths are static, a mismatch
  fails compilation.
- L0C→UB 1-byte destinations (`i8`/`u8`/`f8e4m3fn`/`hif8`): Fixpipe
  always RoundUp's the write axis (RowMajor `N` / ColumnMajor `M`)
  to a 32-element block, independent of `unit_flag`. Static UB pitch
  must be `>= RoundUp(extent, 32)` (RowMajor `stride0`, ColumnMajor
  `stride1`), or pad overwrites the next row / goes OOB. Prefer
  aligning the write-axis extent to 32. With `unit_flag != 0`, mmad
  counts fractals by 16, so a static unaligned extent also hangs;
  the frontend then requires `N % 32 == 0` (RowMajor) or
  `M % 32 == 0` (ColumnMajor). `unit_flag=0` only removes the hang —
  pitch must still cover the RoundUp write (and mmad must use flag
  sync). Dynamic extents/pitches skip these checks (caller
  contract). GM 1-byte destinations are not under this rule.
- **Prepacked `GM` tiles:** a buffer already packed in fractal order is
  tagged `zN` (or `nZ` for the transposed packing) and copied to the
  matching `L1` tile with no re-layout. Only the aligned `zN` / `nZ` are
  `GM` source tags — the tight M-axis is `zNUnAlign` on the `UB`→`L1`
  route, and the `GM` `zNUnAlign` route is the NC1HWC0 feature map that
  feeds `tla.experimental.img2col`. Size both ends for the padded tile:
  `ceil(M/16) * 16` rows for `zN`, and `ceil(M/C0) * C0` rows by
  `ceil(N/16) * 16` columns for `nZ`, since the block move walks whole
  fractals and the last row group travels in full.
- Whole-tile DMA uses `tla.copy`. For register-level UB unaligned
  access, use `tensor.load` / `tensor.store` with `UnalignLoadParams` /
  `UnalignStoreParams`.
- **Shapes not aligned to 32 bytes:** C0 is 32 bytes. For ND GM↔UB,
  prefer a leading dimension whose byte size is a multiple of 32.
  Otherwise keep `origin_shape` as the real size and enlarge the
  physical layout, or use unaligned load/store.

The fixpipe support on-the-fly quant and relu, quant mode support `NO_QUANT`, `PER_TENSOR`, `PER_CHANNEL`.
The fixpipe has these rules:
- the fixpipe chain is (l0c acc) -> quant(optional) -> relu(optional) -> copy out to dst.
- `NO_QUANT` mode includes pure data cast, `f32`->`f16`, `f32`->`bf16`
- If the dst is ub, there's an extra `split_mode`, support nosplit(`NO_SPLIT_VEC_0`, `NO_SPLIT_VEC_1`), and split(`SPLIT_M`, `SPLIT_N`)
- If dst is (ub, ColumnMajor), only support `nosplit` mode
- In to ub is `split` mode, any quant_mode/relu is disabled, neither pure cast, so only `f32`->`f32` and `i32`->`i32` is enabled

|`ub`|`zNUnAlign`|`l1`|`zN`|`f32`,`f16`,`bf16`,`i8`,`f8e4m3fn`,`f8e5m2`,`hif8`|


Supported CopyPad routes, `tla.copy(dst, src, params=CopyPadParams(...))`.
Enables AscendC DataCopyPad (`isPad=true`) on GM→UB (vector) or
GM→L1 VectorLayout→VectorLayout (cube). GM→UB opens hif8/fp8/fp4x2/i4x2
(scalar `f4e2m1`/`f4e1m2` Pad stay closed); GM→L1 adds hif8 only
(fp8/fp4 Pad stay closed on GM→L1).
Side counts must not be bool/tla.Bool/i1; a static side count must
satisfy pad bytes ≤ 32B; with static extents, dst innermost ≥
src + left + right. See Constraints for `padding_value` dtype rules
(including 8-bit integer bit patterns for hif8/fp8/fp4x2/i4x2).

|`src_addr`|`src_layout`|`dst_addr`|`dst_layout`|`dtypes`|
|----------|------------|----------|------------|--------|
|`gm`|`RowMajor`|`ub`|`RowMajor`|`f32`,`f16`,`bf16`,`i32`,`u32`,`i16`,`u16`,`i8`,`u8`,`i1`,`i64`,`u64`,`f64`,`hif8`,`f8e4m3fn`,`f8e5m2`,`f4e2m1x2`,`f4e1m2x2`,`i4x2`|

|`gm`|`VectorLayout`|`l1`|`VectorLayout`|`f32`,`f16`,`bf16`,`i32`,`u32`,`i16`,`u16`,`i8`,`u8`,`i1`,`i64`,`u64`,`f64`,`hif8`|

```python
# --- 1) Aligned GM ↔ UB (RowMajor, 32B-friendly) ---
with tla.vector():
    tla.copy(dst=x_ub, src=x_gm)
    tla.copy(
        dst=x_ub,
        src=x_gm,
        cache_policy=tla.params.CachePolicy.DISABLE,
    )  # optional L2 hint on GM src
    tla.copy(dst=y_gm, src=y_ub)

# --- 2) ND → zN: GM RowMajor → L1 zN ---
l1_a = tla.make_tensor_like(l1_ptr, gm_a, layoutTag=tla.arch.zN)
with tla.cube():
    tla.copy(dst=l1_a, src=gm_a)

# --- 3) M not a multiple of 16: zNUnAlign ---
# Before: rows may be runtime and not a multiple of 16.
l1_unalign = tla.make_tensor_like(l1_ptr, gm_tile, layoutTag=tla.arch.zNUnAlign)
with tla.cube():
    tla.copy(dst=l1_unalign, src=gm_tile)

# Batched FP8: both tensor layouts carry the batch geometry.
# src_step and dst_step are independent element strides.
src3 = tla.make_tensor(src_ptr, tla.make_layout(
    tla.make_shape(batch_count, valid_rows, 128),
    tla.make_stride(src_step, 128, 1)))
dst3 = tla.make_tensor(dst_ptr, tla.make_layout(
    tla.make_shape(batch_count, (16, 8), (32, 4)),
    tla.make_stride(dst_step, (32, 512), (1, 4096)),
    origin_shape=tla.make_shape(batch_count, valid_rows, 128),
    layoutTag=tla.arch.zN))
with tla.cube():
    tla.copy(dst3, src3)

# --- 4) Prepacked GM zN: a plain block move, no re-layout ---
# The host buffer is already zN-packed and padded to ceil(M/16) * 16 rows.
# Both ends carry the same tree, so the copy reorders nothing.
gm_zn = tla.make_tensor(
    gm_ptr, tla.make_layout_with_tag((m_pad16, k), dtype_a, tla.arch.zN)
)
l1_zn = tla.make_tensor_like(l1_ptr, gm_zn, tla.arch.zN)
with tla.cube():
    tla.copy(dst=l1_zn, src=gm_zn)

# --- 5) Prepacked GM nZ: the transposed packing, same idea ---
# nZ pads both axes -- ceil(M/C0) * C0 rows by ceil(N/16) * 16 columns --
# and the copy steps whole C0-row groups, so both buffers carry it.
gm_nz = tla.make_tensor(
    gm_ptr, tla.make_layout_with_tag((m_pad_c0, n_pad16), dtype_a, tla.arch.nZ)
)
l1_nz = tla.make_tensor_like(l1_ptr, gm_nz, tla.arch.nZ)
with tla.cube():
    tla.copy(dst=l1_nz, src=gm_nz)

# --- 6) Flat contiguous run: VectorLayout ---
# A 1-N bias row is one run of elements, not a (1, N) tile. Both
# endpoints of the staging pipeline carry the same tag: GM -> L1 first,
# then L1 -> the bias table buffer.
gm_bias = tla.tile_view(gm_bias_full, tla.make_shape(n), tla.make_coord(0))
l1_bias = tla.make_tensor_like(l1_bias_ptr, gm_bias, tla.arch.VectorLayout)
l0_bias = tla.make_tensor_like(l0_bias_ptr, l1_bias, tla.arch.VectorLayout)
with tla.cube():
    tla.copy(dst=l1_bias, src=gm_bias)
    tla.copy(dst=l0_bias, src=l1_bias)
    tla.mmad(l0_c, l0_a, l0_b, init_c=True, unit_flag=0, bias=l0_bias)
```

## `tla.Tensor.load`

**Source:** [`catlass.tla.tensor._Tensor.load`](../../../../catlass/tla/tensor.py)

Description:

Load this UB tensor tile into vector or mask SSA (`tile.load`).

Prototype:

```python
tla.Tensor.load(params: LoadParams | None = None) -> MaskSSA | VectorSSA | tuple[VectorSSA, VectorSSA] | tuple[VectorSSA | tuple[VectorSSA, VectorSSA], _Tensor]
```

Parameters:

- `params` (`LoadParams | None`): Load mode. Optional, default `None`.
  - `None` / `NormalLoadParams` / `UnalignLoadParams` /
    `BlockLoadParams` → `VectorSSA` (or a pair for
    `DIST_DINTLV_B8` / `DIST_DINTLV_B16` / `DIST_DINTLV_B32`).
  - `MaskLoadParams` → `MaskSSA`.
  - `NormalLoadParams`:
    - `load_dist` (`str`): `tla.params.LoadDist` token. Default
      `DIST_NORM`.

      | Value | Meaning |
      |---|---|
      | `DIST_NORM` | Default contiguous load |
      | `DIST_BRC_B8` | Broadcast one b8 element to all 256 lanes |
      | `DIST_BRC_B32` | Broadcast one b32 element to all lanes |
      | `DIST_DINTLV_B8` | Load 512 bytes; even/odd b8 elements fill two 256-lane vectors |
      | `DIST_DINTLV_B16` | Load 512 bytes; return two 128-lane b16 registers, even positions first and odd positions second |
      | `DIST_DINTLV_B32` | Deinterleave 32-bit words into two vectors. Supports f32/i32/u32, plus i64/u64/f64 with UPDATE. |
      | `DIST_US_B8` / `DIST_US_B16` | 2x up-sample |
      | `DIST_DS_B8` / `DIST_DS_B16` | Load 512 bytes and retain every other b8/b16 element into one full vector |
      | `DIST_BRC_B16` | Broadcast one b16 element |
      | `DIST_UNPACK_B8` | Load 128 b8 elements; insert one zero byte after each into a 256-lane vector |
      | `DIST_UNPACK_B16` | Zero-extend b16 to double width |
      | `DIST_UNPACK_B32` | Load 32 b32 elements; insert one zero b32 element after each into a 64-lane vector |
      | `DIST_UNPACK4_B8` | Load exactly 64 bytes into register byte slots 0,4,...,252; zero the other register bytes |
      | `DIST_E2B_B16` / `DIST_E2B_B32` | Element-to-DataBlock broadcast |
      | `DIST_BLK` | One 32-byte DataBlock broadcast to all 8 |

    - `post_mode` (`str`): `POST_MODE_NORMAL` (default) or
      `POST_MODE_UPDATE`.
    - `post_update_stride` (`Any`): Element stride when
      `post_mode=POST_MODE_UPDATE`; `0` advances by `tile_extent`
      (`origin_shape`). Default `0`.
  - `UnalignLoadParams`:
    - `load_dist` (`str`) defaults to `DIST_NORM` for a single-register
      load. `DIST_DINTLV_B8`, `DIST_DINTLV_B16` and
      `DIST_DINTLV_B32` select a dual load and require `POST_MODE_UPDATE`.
    - `post_mode` (`str`): `POST_MODE_NORMAL` (default) or
      `POST_MODE_UPDATE`.
    - `post_update_stride` (`Any`) defaults to `0`. With
      `POST_MODE_UPDATE`, `0` advances by `origin_shape`.
      The effective stride must be in `(0, VL]` elements for a
      single-register load or `(0, 2 * VL]` elements for a dual load.
      `VL` is the element count of one 256-byte register.
  - `BlockLoadParams`:
    - `block_stride` (`int`): Heads apart in 32B DataBlocks; `0`
      repeats the first block into all 8 slots. Default `0`.
    - `post_mode` (`str`): `POST_MODE_NORMAL` (default) or
      `POST_MODE_UPDATE`.
    - `repeat_stride` (`Any`): Compile-time pre-offset in 32B
      blocks; with `POST_MODE_UPDATE`, the post-update stride.
      Default `0`.
  - `MaskLoadParams`:
    - `load_dist` (`str`): `tla.params.MaskLoadDist` token.
      Default `DIST_NORM`.

      | Value | Meaning |
      |---|---|
      | `DIST_NORM` | Bit-packed mask load |
      | `DIST_US` | Bit upsample |
      | `DIST_DS` | Bit downsample |

Constraints:

- Must be called inside a `@tla.kernel`-decorated kernel function.
- Must be called inside `tla.vec.func(mode="simd")`; source tile must be UB.
- The actual read range must stay within the usable UB address space.
- Mask load ``DIST_NORM`` requires a b8/b16/b32/b64 scalar UB element type.
- Width-suffixed distributions require the corresponding element storage width,
  with a b64 exception for `DIST_DINTLV_B32` in UPDATE. b8 includes Bool and
  byte encodings. `DIST_BLK` supports b8/b16/b32. For single-vector b64 loads,
  use `DIST_NORM` or a full 32-lane `UnalignLoadParams` load.
- `DIST_DINTLV_B8` supports i8/u8/f8E4M3FN/f8E5M2/HiFloat8/E8M0 and packed
  Float4E2M1x2/Float4E1M2x2. Each register
  holds 256 one-byte elements; one load reads `2 * 256 = 512` bytes
  and returns two full vectors of the source type, even positions
  first and odd positions second. For input `[a0, a1, a2, a3, ...]`,
  the results are `[a0, a2, ...]` and `[a1, a3, ...]`. The source
  address must be 32-byte aligned and all 512 bytes must be valid,
  independently of the tile shape. For FP4x2, each element is one byte
  holding two FP4 values. The load deinterleaves these packed bytes
  without changing their two nibbles; each result holds 256 packed
  elements (512 FP4 values). E8M0 is transported as raw bytes, including
  the 0xFF NaN encoding, and can be written back with a normal aligned
  store; arithmetic and register casts are unsupported. Logical
  (unpacked) FP4 is not supported. Bool is supported as b8
  move-only transport (same as i8).
- `DIST_DINTLV_B16` requires a 32-byte-aligned source address.
- `DIST_UNPACK4_B8` requires a 1-byte element type and a
  32-byte-aligned source address.
- `DIST_BRC_B8` / `DIST_DS_B8` / `DIST_UNPACK_B8` support
  Bool/i8/u8/f8E4M3FN/f8E5M2/hif8/f8e8m0/fp4x2; `DIST_DS_B16` supports
  f16/bf16/i16/u16; `DIST_UNPACK_B32` supports f32/i32/u32.
  These modes preserve the source element type and produce full
  256-byte vector registers.
  `DIST_BRC_B8` requires 1-byte source alignment; the other four
  require 32-byte alignment. `DIST_UNPACK_B8` / `DIST_UNPACK_B32` read 128 bytes;
  DS reads 512 bytes. The caller must provide the
  complete valid source range, independently of the tile shape.
- `BlockLoadParams` follows AscendC ``DATA_BLOCK_COPY``
  (b8/b16/b32; b8 includes i8/u8, Bool as b8);
  `block_stride` and `repeat_stride` must fit in [0, 65535].
- ``DIST_US`` / ``DIST_DS``: UB element type may be any
  b8/b16/b32/b64 scalar. The element type only types the UB
  address; the mask bit layout does not depend on element width.
  When the static tile-shape product is in ``{32,64,128,256}``,
  it is used as ``N`` on ``!tla.mask<N>``; otherwise ``N=256``.
- Mask load byte-offset alignment (UB byte address =
  base + offset×sizeof(T)): ``DIST_NORM`` → ``VL/8``;
  ``DIST_US`` → ``VL/16``; ``DIST_DS`` → ``min(32, VL/4)``.
  On VL=256 this is 32B / 16B / 32B.
- Single-vector aligned `POST_MODE_UPDATE` uses `DIST_NORM`
  and accepts b8/b16/b32/b64
  (Bool, i/u integers, FP8, HiFloat8, E8M0, FP4x2, f16, bf16,
  f32 and f64). Returns
  `(vector, next_tile)`. Inside `tla.vec.func`, assign
  `next_tile` back with `tla.range` (`while` is not supported
  nested in `vec.func`). The window must already be an origin
  tile (`coord=0`); cut it with `tile_view` (or equivalent).
  UPDATE never automatically folds non-zero coordinates.
  `NormalLoadParams`: `post_update_stride=0` (default) advances
  by `tile_extent` (`origin_shape`); an explicit stride keeps
  fill / stride-advance decoupling. `UnalignLoadParams` with
  `DIST_NORM` uses `tile_extent` when the stride is `0`.
  The effective stride must be in `(0, VL]`. On a clean `tla.range`,
  `tla-unalign-ureg` hoists Pre/Post out of the loop.
  A dynamic `if` inside the loop keeps both
  instructions in each iteration.
- Aligned `DIST_DINTLV_B8`, `DIST_DINTLV_B16` and `DIST_DINTLV_B32` UPDATE
  return `((even, odd), next_tile)`. Each access reads 512 bytes from a
  rank-1 contiguous UB tile at `coord=0`. The start address and the stride
  in bytes must be 32-byte aligned. The compiler rejects statically known
  misalignment. The caller guarantees alignment for runtime addresses and
  strides. `post_update_stride` is in elements and
  defaults to the tile's `origin_shape`. In UPDATE, B32 also accepts
  i64, u64 and f64 in single-register vectors and deinterleaves 32-bit words.
- Use the same DINTLV distributions with `UnalignLoadParams` and
  `POST_MODE_UPDATE` for unaligned UB addresses. The return value
  is `((even, odd), next_tile)`. The compiler emits two unaligned
  loads that share one `ureg`. The stride defaults to
  `origin_shape` and must be in `(0, 2 * VL]` elements. Only
  lanes corresponding to the first `post_update_stride` effective
  source elements are guaranteed for a partial transfer.
  Allocate backing UB space for two full registers. The compiler
  carries the load alignment state when it proves a full-stride
  loop is safe and initializes it per access otherwise.

Example:

```python
with tla.vec.func(mode="simd"):
    x_reg = x_ub.load()
    x_unalign = x_ub.load(tla.params.UnalignLoadParams())
    x_blk = x_ub.load(tla.params.NormalLoadParams(
        load_dist=tla.params.LoadDist.DIST_BLK))
    x_gather = x_ub.load(tla.params.BlockLoadParams(block_stride=4))
    preg = mask_ub.load(
        tla.params.MaskLoadParams(load_dist=tla.params.MaskLoadDist.DIST_DS)
    )
    y = tla.where(preg, x_reg, min_reg)
    # fp8_ub: 64 Float8E4M3FN elements at a 32-byte-aligned address.
    fp8_reg = fp8_ub.load(tla.params.NormalLoadParams(
        load_dist=tla.params.LoadDist.DIST_UNPACK4_B8))
    fp32_reg = fp8_reg.to(tla.Float32)
```

## `tla.Tensor.store`

**Source:** [`catlass.tla.tensor._Tensor.store`](../../../../catlass/tla/tensor.py)

Description:

Store vector or mask SSA into this UB tensor tile (`tile.store`).

Prototype:

```python
tla.Tensor.store(value: VectorSSA | MaskSSA | tuple[VectorSSA, VectorSSA], params: StoreParams | None = None, *, mask: MaskSSA | None = None) -> _Tensor | None
```

Parameters:

- `value` (`VectorSSA | MaskSSA | tuple[VectorSSA, VectorSSA]`):
  `VectorSSA` or `MaskSSA` to store. For `DIST_INTLV_B8` /
  `DIST_INTLV_B16` / `DIST_INTLV_B32`, pass a two-vector tuple
  `(even, odd)` (same types / full VL). Required.
- `params` (`StoreParams | None`): Store mode. Optional, default
  `None`.
  - `None` / `NormalStoreParams` / `UnalignStoreParams` /
    `BlockStoreParams` → vector store.
  - `MaskStoreParams` → aligned mask store.
  - `UnalignMaskStoreParams` → unaligned packed mask store.
  - `NormalStoreParams`:
    - `store_dist` (`str`): `tla.params.StoreDist` token. Default
      `DIST_NORM`.

      | Value | Meaning |
      |---|---|
      | `DIST_NORM` | Default contiguous store |
      | `DIST_PACK_B16` | AscendC same-type PK_B16 (b16→b16, or b8→b8 after prior cast) |
      | `DIST_PACK_B32` | AscendC same-type PK_B32 (b32→b32, or b16→b16 after prior cast) |
      | `DIST_PACK_B64` | Pack the low 32 bits of i64, u64 or f64 lanes |
      | `DIST_PACK4_B32` | Store register byte slots 0,4,...,252 to UB byte slots 0,1,...,63, subject to the mask |
      | `DIST_INTLV_B8` | Interleave two b8 registers into consecutive dst elements |
      | `DIST_INTLV_B16` | Interleave two b16 registers |
      | `DIST_INTLV_B32` | Interleave 32-bit words from two vectors. Supports f32/i32/u32, plus i64/u64/f64 with UPDATE. |
      | `DIST_FIRST_ELEMENT_B8` | Write only lane 0 (1-byte) |
      | `DIST_FIRST_ELEMENT_B16` | Write only lane 0 (2-byte) |
      | `DIST_FIRST_ELEMENT_B32` | Write only lane 0 (4-byte) |

    - `post_mode` (`str`): `POST_MODE_NORMAL` (default) or
      `POST_MODE_UPDATE`.
    - `post_update_stride` (`Any`): Element stride when
      `post_mode=POST_MODE_UPDATE`; `0` advances by `tile_extent`
      (`origin_shape`). Default `0`.
  - `UnalignStoreParams`:
    - `store_dist` (`str`) defaults to `DIST_NORM` for a single-register
      store. `DIST_INTLV_B8`, `DIST_INTLV_B16` and
      `DIST_INTLV_B32` select a dual store and require `POST_MODE_UPDATE`.
    - `post_mode` (`str`): `POST_MODE_NORMAL` (default),
      `POST_MODE_UPDATE`, or `POST_MODE_UPDATE_NBYTES`.
    - `post_update_stride` (`Any`) defaults to `0`. With
      `POST_MODE_UPDATE`, `0` advances by `origin_shape`.
      The effective stride must be in `(0, VL]` elements for a
      single-register store or `(0, 2 * VL]` elements for a dual store.
      `VL` is the element count of one 256-byte register.
      With `POST_MODE_UPDATE_NBYTES`, use `0`.
  - `BlockStoreParams`:
    - `block_stride` (`int`): Heads apart in 32B DataBlocks.
      Default `0`.
    - `post_mode` (`str`): `POST_MODE_NORMAL` (default) or
      `POST_MODE_UPDATE`.
    - `repeat_stride` (`Any`): Used with `POST_MODE_UPDATE` as the
      post-update stride in 32B blocks. Default `0`.
  - `MaskStoreParams`:
    - `store_dist` (`str`): `tla.params.MaskStoreDist` token.
      Default `DIST_NORM`.
  - `dst.store(mask, tla.params.UnalignMaskStoreParams())` packs
    `mask` into one bit per lane and writes it to `dst`, a rank-1
    contiguous UB window at `coord=0`. A b16 store writes 16 bytes
    and requires a 16-byte-aligned starting address. A b32 store
    writes 8 bytes and requires an 8-byte-aligned starting address.
    The returned tile begins at the starting address of `dst` plus
    the number of bytes written and can be used for the next store.
    It retains the pointer type of `dst`, including its alignment
    declaration. The caller must ensure that the actual address
    meets the alignment required by each operation using the tile.
- `mask` (`MaskSSA | None`): Optional predicate for vector stores;
  rejected by `UnalignStoreParams`, `MaskStoreParams`,
  `UnalignMaskStoreParams`, first-element and interleaved modes.
  Default `None`. For `DIST_PACK4_B32`, masks use source lanes:
  4/2/1 lanes per destination byte for 1/2/4-byte sources.
  An omitted mask follows the destination's valid length;
  an explicit mask is not clipped to that length. Masked-out
  destination bytes remain unchanged.

Constraints:

- Must be called inside a `@tla.kernel`-decorated kernel function.
- Must be called inside `tla.vec.func(mode="simd")`; destination tile must be UB.

**`POST_MODE_NORMAL` mode**

- `DIST_PACK4_B32` supports matching 4-byte element types.
  It also supports 1/2/4-byte source elements with a 1-byte
  destination. It writes at most 64 bytes to a 32-byte-aligned
  address. For FP32→FP8, use `RegSlot.ZERO` to place the
  converted values in byte slots 0,4,...,252 before storing.
- `DIST_PACK_B16` / `DIST_PACK_B32` / `DIST_PACK_B64` require
  matching source and destination element types. B16 accepts
  1- or 2-byte elements, B32 accepts 2- or 4-byte elements, and
  B64 accepts 8-byte elements. Each destination element has room
  for two active source lanes.
- `DIST_INTLV_B8` / `DIST_INTLV_B16` / `DIST_INTLV_B32` require a
  two-vector `value` tuple of identical full-VL registers matching
  the destination element type. B8 supports Bool/i8/u8/f8*/hif8/e8m0/fp4x2.
  B16 supports f16/bf16/i16/u16. B32 supports f32/i32/u32, plus i64/u64/f64
  with UPDATE. Predicate masks are rejected.
- First-element modes require the stored value and the dest tile to
  use the suffix-matching element width (b8 → 1-byte, b16 → 2-byte,
  b32 → 4-byte); passing a predicate mask raises an error.
- `UnalignStoreParams` in NORMAL mode writes up to one vector of
  elements using the destination's valid length. In UPDATE mode,
  the effective stride sets both the write length and pointer advance.

```python
with tla.vec.func(mode="simd"):
    y_ub.store(y_reg)
    y_ub.store(y_reg, tla.params.UnalignStoreParams())
    y_ub.store(y_reg, tla.params.NormalStoreParams(
        store_dist=tla.params.StoreDist.DIST_FIRST_ELEMENT_B16))
    # fp32_reg: 64 FP32 lanes; fp8_ub: 64 Float8E4M3FN elements.
    # fp8_ub starts at a 32-byte-aligned address.
    fp8_reg = fp32_reg.to(tla.Float8E4M3FN, tla.params.CastParams(
        round_mode=tla.params.RoundMode.CAST_RINT,
        sat_mode=tla.params.SatMode.SAT,
        reg_slot=tla.params.RegSlot.ZERO))
    fp8_ub.store(fp8_reg, tla.params.NormalStoreParams(
        store_dist=tla.params.StoreDist.DIST_PACK4_B32))
```

- Single-vector aligned `POST_MODE_UPDATE` uses `DIST_NORM`
  with matching source and destination element types of width
  b8/b16/b32/b64. It returns the next tile. Inside `tla.vec.func`, assign it back with
  `tla.range`. Same origin window (`coord=0`) contract as UPDATE
  `load`. `NormalStoreParams`: default `post_update_stride=0`
  advances by `tile_extent` (`origin_shape`); an explicit stride is
  decoupled. `UnalignStoreParams` with `DIST_NORM` uses `tile_extent`
  when the stride is `0`. The effective stride must be in `(0, VL]`.
  The compiler can hoist Pre/Post out of the loop.
- Aligned `DIST_INTLV_B8`, `DIST_INTLV_B16` and `DIST_INTLV_B32` UPDATE
  write 512 bytes and return the next tile. The compiler advances the
  address after issuing the aligned interleaved store. These modes use the
  same UB window and stride requirements as dual UPDATE load. In UPDATE,
  B32 also accepts i64, u64 and f64 in single-register vectors and interleaves 32-bit words.
- Use the same INTLV distributions with `UnalignStoreParams` and
  `POST_MODE_UPDATE` for unaligned UB addresses. The compiler emits
  two unaligned stores that share one `ureg`. The effective
  stride is in `(0, 2 * VL]` elements and sets both the length
  written and the pointer advance. Store writes the prefix of
  the interleaved pair. The compiler reuses the store alignment state
  in eligible loops under the existing UPDATE rules.

For b16 elements, the dual UPDATE load and store advance the UB
windows in a loop.

```python
from catlass.params import LoadDist, NormalLoadParams, NormalStoreParams, PostMode, StoreDist

load = NormalLoadParams(
    load_dist=LoadDist.DIST_DINTLV_B16, post_mode=PostMode.POST_MODE_UPDATE
)
store = NormalStoreParams(
    store_dist=StoreDist.DIST_INTLV_B16, post_mode=PostMode.POST_MODE_UPDATE
)
with tla.vec.func(mode="simd"):
    for _ in tla.range(trips):
        pair, src = src.load(load)
        dst = dst.store(pair, store)
```

**`POST_MODE_UPDATE_NBYTES` mode**

This mode appends data using the byte count recorded by `squeeze`.
Before each append, call `squeeze(..., record_nbytes=True)` in the
same SIMD region so hardware calculates and records the byte count.
Before that count is overwritten, call `store` with
`UnalignStoreParams(post_mode=POST_MODE_UPDATE_NBYTES)`.
`store` takes that many bytes from the start of the source vector
and writes them at the supplied window's base address plus the
current write offset. It advances the offset and returns the
supplied window.

**Usage restrictions**

- Use a contiguous one-dimensional UB window at `coord=0`. The
  source and destination element types must match. Supported types
  are `Float16`, `Float32`, `Int8`, `UInt8`, `Int16`, `UInt16`,
  `Int32`, and `UInt32`. Keep `post_update_stride` at the
  compile-time constant `0` and omit `mask` from `store`.
- Appends in the same SIMD region share the write offset and
  pending tail. Tail writeback uses the destination base address
  of the last `store` executed with `POST_MODE_UPDATE_NBYTES`.
- Reserve space for appends and tail writeback. From the first
  append through SIMD exit and synchronization, keep other reads
  and writes outside the compressed output byte range.
- External calls must preserve the write offset and pending tail
  from initialization through tail writeback, and the byte count
  from when `squeeze` records it until the corresponding `store`
  uses it.

**Example using `POST_MODE_UPDATE_NBYTES`**

The loop appends `[7, 9, 12]` from `src_ub[0:3]` and `[20, 24]`
from `src_ub[128:130]` to the same destination, `dst_ub`. In
this example, the start address of `dst_ub` is 32-byte aligned.

1. **Initialize.** On entry to the SIMD region, the compiler sets
   up a zero write offset and an empty buffer for pending bytes.
2. **Compress and append.** In the first iteration,
   `squeeze(..., record_nbytes=True)` packs three Int16 elements
   and hardware records 6 bytes. The `store` leaves those bytes
   in the hardware buffer and advances the write offset to 6 bytes.
   In the second iteration, hardware records 4 bytes for two kept
   elements, and `store` adds them after the first 6. The 10
   bytes fall short of a 32-byte block, so they stay in the buffer
   as the pending tail. See the
   [`tla.squeeze` reference](../language/simd/compress.md#tlasqueeze).
3. **Write back the tail.** After the loop, the compiler inserts
   a writeback of the 10 buffered bytes to `dst_ub[0:5]`. After
   leaving the SIMD region and synchronizing, the first five
   elements of `dst_ub` are `[7, 9, 12, 20, 24]`.

Example:

```python
# src_ub and dst_ub are separate contiguous Int16 UB windows at coord=0.
# src_ub contains 256 elements, and dst_ub contains 128.
with tla.vec.func(mode="simd"):
    # Use the hardware-recorded byte count for each append.
    update = tla.params.UnalignStoreParams(
        post_mode=tla.params.PostMode.POST_MODE_UPDATE_NBYTES,
    )
    block = tla.make_shape(128)
    for i in tla.range(2):
        # Select source indices 0 through 127, then 128 through 255.
        src_tile = tla.tile_view(src_ub, block, tla.make_coord(i))
        # Keep the first 3 elements of the first tile and the first 2 of the second.
        keep, _ = tla.update_mask(3 - i, dtype=tla.Int16)
        # Pack the kept elements. At 2 bytes per Int16, hardware records 6, then 4 bytes.
        packed = tla.squeeze(src_tile.load(), keep, record_nbytes=True)
        # Pass dst_ub each time. Hardware advances the write offset.
        dst_ub.store(packed, update)
```

## `tla.Tensor.fill`

**Source:** [`catlass.tla.tensor._Tensor.fill`](../../../../catlass/tla/tensor.py)

Description:

Fill this L1 tile with a numeric constant.

Prototype:

```python
tla.Tensor.fill(value: int | float) -> None
```

Parameters:

- `value` (`int | float`): Trace-time scalar, encoded in the
  destination type. Integer destinations require an in-range
  `int`; f16/bf16/f32 destinations accept `int` or `float` and
  reject finite overflow. FP4/FP8 require finite values exactly
  representable in the destination format; out-of-range and inexact
  constants are rejected without rounding. E8M0 requires an exact
  positive power of two in ``[2**-127, 2**127]``; zero, negative
  values and non-powers of two are rejected.

Constraints:

- Must be called inside a `@tla.kernel`-decorated kernel function and
  nested inside `tla.cube()`.
- Destination must be an L1 tensor. Operand types use ``zN`` or
  ``nZ``; E8M0 scales use ``zZMxScale`` or ``nNMxScale``.
- Fill covers ``[coord, coord + origin_shape)``. Operand C0-axis
  boundaries are aligned up to 32-byte units. MX scales align
  the M/N axis to 16 and the scale-group axis to 2; each 16-by-2
  fractal occupies 32 bytes. A partial leading unit is left
  untouched; the final unit may include physical Padding beyond
  the logical extent, which must fit the allocation. Empty
  regions perform no writes.
- Supported element types: ``i16/u16/f16/bf16/i32/u32/f32``,
  packed fp4/fp8 operands
  (``f4e2m1``/``f4e1m2``/``f8e4m3fn``/``f8e5m2``), and ``f8e8m0``.
  8-bit integer destinations are not supported.

Example:

```python
# Zero the K-pad tail of an L1 A tile: tile first, then fill.
pad = tla.get_tile(t_l1a, tla.make_coord(0, k_valid),
                   tla.make_shape(m, k_l0 - k_valid))
pad.fill(0)
# Numeric one is encoded by the destination dtype.
t_l1a.fill(1.0)
t_l1sa.fill(1.0)  # E8M0 scale one, encoded as 0x7f.
```

## `tla.Tensor.__getitem__`

**Source:** [`catlass.tla.tensor._Tensor.__getitem__`](../../../../catlass/tla/tensor.py)

Description:

Load one tensor element as a scalar (`tensor[i]` / `tensor[i, j]`).

Prototype:

```python
tla.Tensor.__getitem__(crd: Any) -> Any
```

Parameters:

- `crd` (`int | Int32 | tuple`): Element coordinate. One index per
  logical dimension of the tensor. Required.

Returns:

- `Numeric`: the element, typed by the tensor's element type
  (`Bool` for an i1 tensor).

Constraints:

- Must be called inside a `@tla.kernel`-decorated kernel function.

  accessed inside `tla.vector()`.

- Logical rank must be 1 or 2, and the number of indices must match

  sub-tensor instead.

Example:

```python
with tla.vec.func(mode="simt", thread_block_dim=256):
    tid, _, _ = tla.arch.thread_idx()
    value = gm_in[tid]
```
